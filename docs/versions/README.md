# docs/versions/ — یک پوشه برای هر نسخه، فایل‌های شماره‌دار، بدونِ بازنویسی

هر نسخه پوشهٔ خودش را دارد: `0.1/`، `0.2/`، `0.3/` …

**فایل‌ها شماره‌دارند و به‌ترتیب اضافه می‌شوند.** هر رفت‌وبرگشت بینِ تو و دستیار یک **دور** است و یک فایلِ تازه؛ فایل‌های قبلی بازنویسی نمی‌شوند. این کلِ قاعده است، و همان چیزی است که تاریخچهٔ واقعیِ تصمیم‌هایت را نگه می‌دارد.

```
docs/versions/0.1/
  00-idea-input.md      ← ایدهٔ خامِ تو
  01-idea-core.md       ← پیش‌نویسِ دستیار
  02-input.md           ← یادداشتِ بعدیِ تو (اگر بود)
  03-questions.md       ← سؤال‌های دستیار؛ جواب‌ها را داخلِ همین فایل می‌نویسی
  05-design-prompt.md   ← متنی که در Claude وب پیست می‌کنی
  06-test-round-1.md    ← یافته‌های تو موقعِ تست
  design-chat.md        ← نامِ ثابت: گفت‌وگوی طراحی، که خودت می‌نویسی‌اش
  checklist.md          ← نامِ ثابت: کارهای همین نسخه
  handoff.md            ← نامِ ثابت: چیزی که گامِ نقشه برای گامِ ساخت می‌گذارد
```

- به واقع **`0.1/`** با ایدهٔ خامِ تو شروع می‌شود (`00-idea-input.md`) و با بسته‌شدنِ نسخه تمام می‌شود.
- **بینِ روزِ اول و روزِ دوم:** هر فکرِ تازه‌ای که به سرت زد، یک فایلِ شماره‌دارِ تازه در همین پوشه است. اسمش مهم نیست، شماره‌اش مهم است. روزِ دوم دستیار همه را می‌خواند.
- **نسخه‌های بعدی:** **تو** پوشه را می‌سازی (مثلاً `0.2/`) و خواسته‌ات را در `01-input.md` می‌گذاری، بعد `/iterate` را می‌زنی. دستیار خودش آخرین پوشه را پیدا می‌کند. بعد سندهای **تغییرات** را آنجا می‌نویسد — یعنی *چه چیزی عوض می‌شود*، نه بازنویسیِ کلِ سند — و فقط بعد از تأییدِ تو سراغِ مستنداتِ زنده می‌رود.
- **پوشهٔ نسخهٔ بسته‌شده خوانده نمی‌شود.** دستیار فقط پوشهٔ نسخهٔ فعلی را می‌خواند، مگر اینکه تو خودت فایلِ خاصی را نام ببری.

مستنداتِ **زنده** (`docs/living/`) همیشه وضعِ فعلی را نشان می‌دهند و اینجا نگه‌داری نمی‌شوند.
