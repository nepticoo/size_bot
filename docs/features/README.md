# docs/features/ — یک فایل برای هر قابلیت

هر بار که یک قابلیت تصمیم گرفته می‌شود، همان لحظه یک فایل می‌گیرد: `docs/features/<اسمِ-کوتاه>.md`.

هر فایل سه چیز دارد:

۱. این قابلیت **چه می‌کند** (به زبانِ ساده، از دیدِ کاربر).
۲. **از کجا می‌فهمیم کار می‌کند** — کدام سناریوی تست آن را ثابت می‌کند.
۳. در **کدام نسخه** اضافه شد.

تفاوتش با `prd.md` چیست؟ به واقع `prd.md` می‌گوید محصول **الان چیست**؛ این پوشه می‌گوید **چه چیزی، کِی، و چرا** اضافه شد. دو کارِ متفاوت‌اند و نباید در هم حل شوند.
